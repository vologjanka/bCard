О чём этот урок
---------------
Мы добавили «настоящего почтальона» в интернет: после проверки полей форма
отправляет JSON на сервис Web3Forms, а письмо приходит на почту, которую вы
указали при создании ключа на web3forms.com.

Важно сказать детям в начале
----------------------------
Реплика: «Раньше зелёное “спасибо” было как тренировочный светофор — мы сами
решали, что “всё ок”. Теперь светофор зажигается только если далекий сервис
сказал: “письмо принято”.»

Реплика: «Ключ от сервиса живёт в файле .env на компьютере — его не клеим
в открытый GitHub, как не клеят код от домофона на подъезд.»

Как пользоваться папкой с файлами insert-*.txt
----------------------------------------------
• Каждый файл — ОДНА операция: вставить новый кусок или заменить старый.
• Делайте по порядку: 00, 01, 02, … После каждого шага сохраняйте файл и
  смотрите, не появились ли красные подчёркивания в редакторе.
• Если у вас уже «полная» версия как у преподавателя — эти вставки не нужны,
  это раздаточный материал для тех, кто догоняет с нуля.

БЛОК 3. Два новых состояния (после isSuccess)
--------------------------------------------------------------------------------
За что отвечает:
• isSubmitting — «ждём ответ из интернета»; кнопку блокируем, чтобы не отправить
  форму десять раз подряд.

  подсказки под полями (имя, email…).

Реплика: «Две новые коробочки памяти. В одной — “идёт отправка”, в другой —
“что пошло не так с дорогой”, если не интернет-поле, а дорога до сервиса.»

--------------------------------------------------------------------------------
БЛОК 4. Начало handleSubmit: async и сброс submitError
--------------------------------------------------------------------------------
За что отвечает:
• async — разрешает использовать await внутри функции (подождать ответ сервера).
• setSubmitError('') сразу после preventDefault — при новой попытке стираем
  старое красное сообщение про сеть.

Реплика: «Слово async — как сказать программе: “тут будут паузы, подожди
ответ, не торопись дальше по строчкам”.»

Файл для копирования: 03-handleSubmit-async-i-sbros-submitError.txt

--------------------------------------------------------------------------------
БЛОК 5. Вместо «мгновенного успеха» — ключ, fetch, try/catch/finally
--------------------------------------------------------------------------------
За что отвечает (после блока if (hasError) { … return }):
• Читает ключ из import.meta.env (Vite подставляет из .env).
• Если ключа нет — понятное сообщение, return.
• fetch POST с JSON: access_key, subject, name, email, message.
• Разбирает ответ; если HTTP не ок или success не true — пишет в submitError.
• Если всё хорошо — зелёный успех и очистка полей, как раньше.
• finally всегда снимает «отправляем…» с кнопки.

Реплика: «До этого момента мы даже не звонили в интернет, если поля кривые.
Теперь звоним только когда анкета зачётная.»

Реплика: «try — попробуй дорогу, catch — если обрыв провода, finally — снять
надпись “занято” с кнопки в любом случае.»

Файл для копирования: 04-handleSubmit-web3forms-posle-validacii.txt
