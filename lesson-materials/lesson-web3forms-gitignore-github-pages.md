## Часть 1. Web3Forms — куда зайти и что сделать

### Шаг 1. Открыть сайт сервиса
Зайти в браузере на: **https://web3forms.com**

### Шаг 2. Получить ключ (Access Key)
1. Указать **email**, на который должны приходить письма с формы (лучше с разрешения взрослого / школьный проектный ящик).  
2. Нажать получить **Access Key** (формулировки на сайте могут слегка отличаться — ищите кнопку вроде *Get Started* / *Create Access Key*).  
3. **Скопировать ключ** в надёжное место (блокнот преподавателя / менеджер паролей).  
4. (По желанию) В кабинете Web3Forms включить **ограничение по домену** (например только `ваш-ник.github.io`), чтобы форму не дергали с чужих сайтов.

### Шаг 3. Что такое ключ простыми словами
- Это **не** пароль от почты.  
- Это **идентификатор формы** у Web3Forms: сервис понимает, *куда* слать письмо.

## Часть 2. Что прописать в проекте (Vite + React)

Рабочая папка проекта: **`my-app`** (там лежит `package.json`).

### 1) Создать файл `.env` в `my-app`
**Имя файла ровно:** `.env` (с точкой в начале).  
**Содержимое (одна строка, без кавычек):**

```env
VITE_WEB3FORMS_ACCESS_KEY=вставьте_сюда_скопированный_ключ
```

**Почему `VITE_` в начале имени?**  
Vite **разрешает** попадание в сайт только переменных с префиксом `VITE_`. Иначе секреты случайно не утекли бы в браузер — но здесь ключ **и так** предназначен для использования на сайте (это нормально для Web3Forms; всё равно не кладём его в git).

### 2) Перезапустить сервер разработки
После создания/изменения `.env`:

```powershell
cd C:\js\react\bCard\my-app
npm run dev
```

Если dev-сервер уже был запущен — **остановить** (Ctrl+C) и запустить снова.

### 3) Код формы (идея для урока)
В компоненте формы (у вас это `ContactSection.tsx`) после **успешной проверки полей** нужно отправить **POST** на:

`https://api.web3forms.com/submit`

**Тело запроса (JSON), пример:**

```json
{
  "access_key": "СЮДА_ТОТ_ЖЕ_КЛЮЧ_ИЛИ_ИЗ_import.meta.env",
  "subject": "Письмо с визитки",
  "name": "Имя из поля",
  "email": "Email из поля",
  "message": "Текст сообщения"
}
```

**В React/Vite ключ читают так:**

```ts
const accessKey = import.meta.env.VITE_WEB3FORMS_ACCESS_KEY
```

**Если ключа нет** (забыли `.env`) — показать детям понятное сообщение на странице: «Попросите преподавателя проверить файл .env».

### 4) Проверка
1. Открыть сайт локально.  
2. Заполнить форму правильно.  
3. Нажать «Отправить».  
4. Проверить **почту**, на которую создавали ключ.

## Часть 3. `.gitignore` — что исключить и почему (объяснение для детей)

Файл **`.gitignore`** говорит Git: **«эти файлы не сохраняй в историю проекта»**.

### 1) `.env` — **обязательно игнорировать**
**Почему:** там ключ. Если залить в открытый GitHub, ключ увидит кто угодно — могут начать спамить вашу форму.

**Как прописать в `.gitignore` (в корне `my-app`):**

```gitignore
.env
.env.local
```

**Полезно добавить пример без секретов** (его **можно** коммитить): файл **`.env.example`**:

```env
VITE_WEB3FORMS_ACCESS_KEY=
```

И строка в `.gitignore`, чтобы не зацепить случайно другие локальные env:

```gitignore
.env
.env.local
```

*(Если используете шаблон `!.env.example`, уточните у преподавателя: в разных шаблонах `.gitignore` это правило работает по-разному. Самый простой путь для детей: **`.env` в ignore**, **`.env.example` без значения ключа** — и всё.)*

### 2) `node_modules` — обычно уже в `.gitignore`
**Почему:** тысячи файлов, они **скачиваются** командой `npm install`. Хранить в git — как хранить в шкафу чужой магазин целиком.

### 3) `dist` — часто в `.gitignore`
**Почему:** это **результат сборки**. Его можно заново получить командой `npm run build`.  
*Исключение:* если у кого-то деплой устроен иначе — у вас используется `gh-pages`, который сам публикует `dist`.

### Аналогия для детей
- **Git** — альбом с **вашими тетрадками** (исходники).  
- **`node_modules`** — набор **готовых учебников из библиотеки**, их не вклеивают в альбом, их **выдают по списку** (`npm install`).  
- **`.env`** — **записка с кодом от шкафчика**, её не приклеивают на обложку альбома.

## Часть 4. Готовый проект на GitHub Pages (подробно, с командами)

### Условия (как у вашего проекта)
- В `vite.config.ts` уже есть **`base: './'`** — важно для GitHub Pages.  
- В `package.json` уже есть скрипты:
  - `"predeploy": "npm run build"`
  - `"deploy": "gh-pages -d dist"`

### Шаг A. Убедиться, что вы в папке `my-app`
```powershell
cd C:\js\react\bCard\my-app
```

### Шаг B. Проверить сборку локально
```powershell
npm run build
```
Если ошибок нет — появится папка `dist`.

### Шаг C. Сохранить изменения в Git (без `.env`!)
```powershell
cd C:\js\react\bCard
git status
```
Убедиться, что **`.env` не в списке на коммит** (если вдруг показывается — значит `.gitignore` не настроен).

Добавить файлы, сделать коммит, отправить:
```powershell
git add .
git commit -m "Подключена форма и подготовка к деплою"
git push
```

### Шаг D. Выложить сайт командой деплоя
```powershell
cd C:\js\react\bCard\my-app
npm run deploy
```

**Что происходит:**
1. Запускается `npm run build` (сборка в `dist`).  
2. Пакет `gh-pages` заливает содержимое `dist` в ветку **`gh-pages`** на GitHub.

### Шаг E. Настройка GitHub Pages в браузере
1. Открыть репозиторий на GitHub.  
2. **Settings** → **Pages**.  
3. **Build and deployment** → Source: **Deploy from a branch**.  
4. Branch: **`gh-pages`**, папка **`/ (root)`**.  
5. Сохранить. Подождать 1–3 минуты.  
6. Открыть ссылку вида:  
   `https://ВАШ_НИК.github.io/ИМЯ_РЕПО/`

## Важно про ключ на GitHub Pages (объяснить детям)

Если ключ лежит **только** в локальном `.env` и **не попал в git**, то:

- локально сборка видит ключ;
- на GitHub Actions (если не настроено) ключ может отсутствовать.

**Самый простой классовый сценарий:**  
перед командой **`npm run deploy`** на машине преподавателя/ученика есть `.env`, выполняется `npm run deploy` — в готовые файлы в ветке `gh-pages` ключ **попадёт как часть JS-сборки** (так работает статический сайт).

**Правило для детей:**  
«`.env` не в git, деплой делаем с компьютера, где файл `.env` существует.»

## Типичные ошибки (что говорить, если “не работает”)

1. **Письма нет** — проверить папку «Спам», подождать 2–3 минуты.  
2. **Локально не отправляет** — не перезапустили `npm run dev` после `.env`.  
3. **На GitHub Pages не отправляет** — деплой делали без `.env` на той машине / не пересобрали.  
4. **`npm run deploy` из не той папки** — должно быть `my-app`, где `package.json`.
